## One-story workflow

1. For an independent re-import, first move/remove the downloaded private draft elsewhere; then run `python scripts/import_selected_story.py --fetch` from the repository root. The script makes **one** HTTPS request to the fixed VyasaOnline story URL, extracts paragraph text from the post body (not navigation/comments/scripts), and writes `data/content/aruni-uddalaka.json` with `review_status: pending`. It stops on the separate “The other stories” heading and **refuses output** unless there are exactly six paragraphs beginning with “ಆರುಣಿ ಉದ್ಧಾಲಕನ ಈ ಕಥೆಯು” and ending with a paragraph beginning “ಉಪಾದ್ಯಾಯನ ಈ ಮಾತುಗಳನ್ನು ಕೇಳಿ”. This verifies basic extraction boundaries only; the six paragraphs still require human review. It does not browse the story index, download other chapters, or update the catalog.
2. If the source layout changes, or you prefer full control, copy only the Kannada story body to a private UTF-8 `.txt` file (separate source paragraphs with blank lines) and run `python scripts/import_selected_story.py private-story.txt` instead. The same six-paragraph boundary check applies to manual input. Never import source HTML, comments, or images; a source revision that changes structure requires manual inspection and an intentional, separately reviewed importer update rather than bypassing the guard.
3. Review **each of the six generated paragraphs** against the primary website page. Check that the introduction and concluding sentence are present; no "The other stories" list, navigation, comment form, or missing Kannada text. Verify spelling, line breaks, order, and source credit. A successful structural gate does **not** constitute full content review. The original website story is prose: do not invent Sanskrit verse numbers or use GitHub chapter text to fill gaps.
4. Paragraph IDs are initially `p0001`, `p0002`, etc. They support resume/bookmarks, but may shift if a later source revision inserts text. Preserve existing IDs manually on revisions; this importer refuses to overwrite its output. A SHA-256 of the imported text, import date, fetch method, and unknown source revision are recorded.
5. After manual source comparison, set the private JSON `review_status` to `approved` **and only then** change `data/catalog.json` for `aruni-uddalaka` to `content_status: approved` and `content_path: "aruni-uddalaka.json"` on the intended private deployment. The Flask loader now requires `review_status: "approved"` for every item with a nonempty original `source_url`; an imported draft cannot be displayed by accidentally approving its catalog entry. Keep the public catalog `link_only` while the private text is unavailable there.
6. Manually verify Kannada display, credit and original link, bookmarks, auto-resume, missing-content fallback, and Android PWA behavior before treating the item as released. Record the outcome in `docs/PROGRESS.md` and `docs/DEVELOPMENT_LOG.md`.
